# آفاق (AFAQ) — منصة استكشاف معرفي مصدرها موثّق حول آيات القرآن الكريم

> **حالة هذا التسليم:** هذا هو إنجاز "المهمة الأولى" المطلوبة في `AFAQ_MASTER_SPEC.md` (فحص المصادر
> المسموح بها + خطة تنفيذ + بنية ابتدائية للاستيعاب والتخزين) مع هيكل كود حقيقي قابل للتشغيل،
> **وليس** منصة منتَجة ومُختبرة بالكامل. السبب: هذه المحادثة تعمل داخل بيئة حاوية مؤقتة بلا اتصال
> شبكي من داخل bash وبلا قاعدة بيانات دائمة، فلا يمكنها تشغيل Docker/FastAPI/Postgres فعليًا أو تنفيذ
> استيعاب حي من الإنترنت والتحقق منه بالاختبارات كما تطلب الفقرة "Claude Code execution method" و
> "Definition of Done". **الخطوة التالية الصحيحة هي فتح هذا المجلد في Claude Code** (تطبيق سطح مكتب/
> طرفية لدى Anthropic يملك شبكة واتصال مستمر وبيئة تشغيل فعلية)، حيث يمكن تثبيت الاعتماديات، تشغيل
> Docker compose، تنفيذ الاستيعاب الحقيقي، وتشغيل الاختبارات وإصلاح الأخطاء فعليًا كما يطلب المستند.

## ما تم فعلاً في هذا التسليم (تم التحقق منه عبر تصفح حقيقي للمصادر)

### 1. القرآن — Quranpedia ✅ مصدر موثوق وموثّق رسميًا
بعد فحص `quranpedia.net` فعليًا (وليس افتراضًا)، تبيّن أنها توفّر **واجهة REST API رسمية موثّقة** على
`https://api.quranpedia.net/v1`، مجانية، بلا مصادقة، JSON، تشمل:
- `/mushafs` و `/mushafs/{id}` — نص كل آية بكل مصحف/رواية (المصحف رقم 1 = حفص).
- `/mushafs/{mushaf_id}/{surah_id}/{ayah_number?}` — آية أو سورة كاملة.
- `/ayah/{surah}/{ayah}/book/{book_id}` — **نص التفسير** من كتاب تفسير محدد لآية محددة.
- `/surah/tafsirs/{surah_id}` — قائمة كتب التفسير المتاحة لكل سورة.
- `/translations/...`, `/topics`, `/search/...`, و **`/v1/changes?since=`** لمزامنة التصحيحات اللاحقة.
- ترخيص بيانات صريح في `https://quranpedia.net/dumps/LICENSE.md`: الاستخدام داخل التطبيقات مجاني
  بلا اشتراط نسب، والنسب واجب فقط عند **إعادة نشر البيانات كقاعدة بيانات قابلة للتنزيل**.
- **سياسة استخدام صريحة تمنع الزحف الجماعي (bulk scraping)** وتحدد حد معدل 120/دقيقة و10,000/يوم،
  وتوجّه من يحتاج نسخة كاملة إلى **Dumps رسمية** (`/dumps`) بدل الزحف — وهذا بالضبط ما يطلبه المستند
  ("Do not blindly scrape... build a documented adapter").

**القرار المعماري:** الاستيعاب يتم عبر هذا الـ API الرسمي (مباشرة لكل آية/تفسير يطلبه المستخدم، أو عبر
Dumps للتحميل الكامل)، وليس عبر استخلاص HTML — هذا يحقق متطلب "لا يُقتبس/يُعاد بناء النص القرآني
آليًا باللغة النموذجية" لأن النص يُخزَّن حرفيًا كما يُعيده الـ API مع `source_url` و`retrieval_date`
و`version` (نُتابع `/v1/changes` بدل إعادة الزحف بالكامل).

### 2. التفسير — Dorar.net ⚠️ لم يُعثر على واجهة API موثّقة مكافئة
محاولات بحث متعددة عن `dorar.net/tafseer`, `dorar.net/article/1955`, و`dorar.net/refs/tafseer` لم
تُظهر توثيق API رسمي علني مكافئ لما تملكه Quranpedia (الموقع لا يظهر جيدًا في نتائج البحث المتاحة لهذه
الجلسة، ومحاولات `web_fetch` المباشرة مرفوضة ما لم يظهر الرابط أولًا في نتيجة بحث). **لم أُثبت بنفسي
وجود أو غياب API لـ Dorar بثقة كافية لبناء مستوعب آلي عليه الآن.**

القرار الآمن المطابق للمستند ("do not blindly scrape... build a documented adapter rather than
bypassing restrictions"): **لا تُبنى حاليًا أي وحدة زحف تلقائي لـ Dorar.net.** الخطوة التالية (ينفَّذها
Claude Code بشبكة فعلية) هي:
1. فتح `https://dorar.net/tafseer/`، `https://dorar.net/article/1955`، و`https://dorar.net/refs/tafseer`
   مباشرة وقراءة `robots.txt` وأي صفحة "شروط استخدام"/API إن وُجدت.
2. إن وُجد API أو تصدير رسمي → بناء adapter موثّق مثل Quranpedia تمامًا.
3. إن لم يوجد → التواصل مع الموقع لطلب إذن/تصدير، أو **الاكتفاء مؤقتًا بكتب التفسير المتوفرة فعليًا عبر
   Quranpedia API نفسها** (`/surah/tafsirs/{surah}` تُعيد بالفعل كتب تفسير مثل "تيسير التفسير" بنصها
   الكامل عبر `/ayah/{s}/{a}/book/{book_id}` — وهذا مصدر تفسير حقيقي وموثّق تحت نفس ترخيص Quranpedia)
   كمصدر تفسير أساسي للمرحلة الأولى، مع تصنيف كل كتاب تفسير حسب مؤلفه كمصدر `TAFSIR_VERIFIED` منفصل.

### 3. العلوم — لا يوجد allowlist نهائي بعد
وفق المستند، يجب بناء قائمة مصادر علمية مسموحة (هيئات حكومية، جامعات، أبحاث محكّمة). هذا القرار
بحاجة لمدخلات من صاحب المشروع (أي النطاقات العلمية ذات الأولوية؟) قبل برمجته، فتُرك كإعداد قابل
للتوسعة في `backend/app/config.py` (`SCIENTIFIC_SOURCE_ALLOWLIST`).

  backend/app/ai_research/       # الذكاء الاصطناعي في الإعجاز العلمي (التعليمات، المحوّلات، وضع الاختبار)

## التشغيل (يُنفَّذ في Claude Code أو بيئة بشبكة فعلية)
```bash
cd afaq
cp .env.example .env            # منصة الذكاء الاصطناعي (AFAQ_AI_PROVIDER، OPENAI_*) ورموز المراجعين (AFAQ_REVIEWERS)
docker compose up -d db
cd backend && pip install -r requirements.txt -r requirements-dev.txt
 # الجداول تُنشأ تلقائيًا عند أول أمر استيعاب أو عند تشغيل الخادم (لا توجد Alembic بعد)
python -m app.ingestion.ingest_kfgqpc                   # نص القرآن كاملًا (6236 آية) من ملف مجمع الملك فهد — انظر أدناه
python -m app.ingestion.ingest_tafsir_dump               # التفسير للقرآن كاملًا من ملفات Quranpedia الرسمية (التفاسير الأساسية)
python -m app.ingestion.ingest_tafsir_dump --books 3,2012  # أو كتب محددة بأرقامها
python -m app.ingestion.ingest_layers_dump              # الصرف، الغريب، الإعراب، الموضوعات، سنوات الوفاة
python -m app.ingestion.ingest_quran_m                  # فهرس مقالات الإعجاز من quran-m.com (نحو 20 دقيقة)
python -m app.curation                                  # خرائط المفاهيم والمعرفة العلمية المعدّة يدويًا (backend/curation/)
pytest                           # اختبارات بمحاكاة الشبكة، تعمل بلا اتصال
uvicorn app.main:app --reload --env-file ../.env   # بدون --env-file لا يقرأ الخادم ملف .env
cd ../frontend && npm ci && npm run dev              # الواجهة على http://localhost:3000
```

## نص القرآن: ملف مجمع الملك فهد (kfgqpc_hafs_v30)
مصدر نص القرآن المعتمد هو إصدار البيانات الرسمي من مجمع الملك فهد لطباعة المصحف الشريف
(`https://qurancomplex.gov.sa/quran-hafs/` — الحزمة `kfgqpc_hafs_v30`)، بدل Quranpedia API.
الملفات **غير موجودة في git** (ترخيص إعادة التوزيع غير مذكور في الحزمة)، فضعها يدويًا:
```bash
cp kfgqpc_hafs_v30-data/kfgqpc_hafs_v30.json  backend/data/
cp kfgqpc_hafs_v30-font/kfgqpc_hafs_v30.ttf   frontend/public/fonts/   # خط عرض الآيات
```
- يُخزَّن `aya_text_unicode` حرفيًا (مع علامة نهاية الآية ورقمها)، ومعه رقم الصفحة والجزء والنص الإملائي.
- يُتحقَّق من الملف كاملًا قبل الكتابة (6236 آية، 114 سورة، ترقيم متصل)، ويُسجَّل SHA-256 للملف في جدول `sources`.
- إن كانت الآيات مستوعبة سابقًا من Quranpedia: `python -m app.ingestion.ingest_kfgqpc --replace` يحدّثها في مكانها
  فتبقى روابط التفسير سليمة.
- أُضيفت أعمدة جديدة لجدول `verses` (`page_number`, `juz_number`, `text_imlaei`)؛ لا توجد Alembic بعد،
  فقاعدة بيانات تطوير قديمة تحتاج إعادة إنشاء (`docker compose down -v`) أو إضافة الأعمدة يدويًا.
- `ingest_quran.py` (Quranpedia) باقٍ كبديل، و`ingest_tafsir.py` ما زال يجلب التفسير من Quranpedia.

## رحلة الآية (من وثيقة فكرة المشروع AFAQ.pdf)
صفحة الآية تعرض الطبقات بالترتيب، وكل عنصر يحمل إحدى فئات الثقة الخمس
(🟢 نص قرآني · 🔵 تفسير موثق · ⚪ حقيقة علمية مثبتة · 🟠 مقارنة/ارتباط محتمل · 🔴 ادعاء غير موثق):
1. **التحليل اللغوي** — صرف كل كلمة (Quranic Arabic Corpus، رخصة GPL مع ذكر المصدر)، ومعاني الغريب من كتبها،
   والإعراب (العكبري، ابن النحاس). ملفات الإعراب مقسّمة بالصفحات، فيُقتطع مقطع الآية نفسها حرفيًا متى وُجد سطرها
   (`is_excerpt`)، وإلا تُعرض الصفحة كاملة مع تنبيه.
2. **التفسير عبر العصور** — التفاسير مرتّبة بسنة وفاة المؤلف، مع القرن والحقبة (المتقدمون، المتوسطون، المتأخرون، المعاصرون).
3. **المفاهيم والظواهر** — خريطة تفاعلية: الآية في المركز، حولها ألفاظها المفتاحية وموضوعاتها القرآنية (Quranpedia)،
   ثم المفاهيم العلمية القابلة للمقارنة. الضغط على موضوع يعرض الآيات الأخرى فيه ويفتحها.
4. **المعرفة العلمية الحديثة** — معطيات علمية بمصادرها، ومقارنات مقترحة مصنّفة «ارتباط محتمل» لا «تفسير».

**خرائط المفاهيم** تُعدّ لكل آية في `backend/curation/<سورة>-<آية>.json`. الموجود الآن 20 آية:

| المحور | الآيات | المفاهيم العلمية | المصدر |
|---|---|---|---|
| البحار والمياه | النور 40، الفرقان 53، الرحمن 20، المؤمنون 18 | المناطق الضوئية، مصبات الأنهار، الحد بين العذب والمالح، المياه الجوفية | NOAA، USGS |
| السماء والفلك | الذاريات 47، الأنبياء 30، الأنبياء 32، الأنبياء 33، يس 40، يونس 5، الحديد 25، النور 43 | تمدد الكون، الانفجار العظيم، الماء والحياة، الأوزون، الشهب، مدار الشمس، ضوء القمر المنعكس، تكوّن الحديد في النجوم، السحب، البرد | NASA، NOAA |
| الأرض | النبأ 7، النحل 15، النمل 88، الحجر 22 | جذور الجبال، حركة الصفائح، التلقيح بالرياح | USGS، USDA |
| الإنسان | الأنعام 125، المؤمنون 13، المؤمنون 14، الإنسان 2 | نقص الأكسجين، حماية الجنين في الرحم، التطور الجنيني، الإخصاب | MedlinePlus (NIH) |

اختيرت آيات الدفعة الثانية من أكثر الآيات تناولًا في مقالات quran-m.com العلمية المركّزة، لكن المعلومات العلمية نفسها
موثقة من الجهات الحكومية لا من الموقع. أُجّلت النحل 66 (اللبن)، والنحل 69 (العسل)، والرعد 12 (ثقل السحاب) لأن
مصادرها على `ncbi.nlm.nih.gov` و`www.usgs.gov` و`www.noaa.gov` المحجوبة في هذه البيئة.
كل مقارنة تذكر معنى اللفظ عند أهل الغريب أولًا، وتصف الربط العلمي بأنه قراءة معاصرة للمقارنة لا تفسير.
`GET /explore` يعيد قائمة هذه الآيات، وتظهر في الواجهة تحت «آيات نموذجية».

**التحقق من المصادر:** كل معلومة علمية تحمل رابط صفحتها واقتباسًا قصيرًا منها. الأمر التالي يفتح كل صفحة ويبحث عن
الاقتباس حرفيًا (بعد توحيد المسافات وعلامات التنصيص)، وعند التطابق يسجّل `verified_at` فتُعرض «حقيقة علمية مثبتة»:
```bash
python -m app.curation --verify   # ثم: python -m app.curation لإعادة التحميل
```
الحالة الحالية: **27/27 معلومة طوبقت مع صفحاتها الأصلية** (3 أكتوبر 2026). وراجعتُ النص العربي لكل معلومة مقابل
الجملة الكاملة في الصفحة، لا الاقتباس وحده. صفحة NSSL للبرد شهادتها الأمنية ناقصة السلسلة، فاستُبدلت بصفحة NESDIS من NOAA.
يحتاج التحقق الوصول إلى النطاقات الفرعية: `*.nasa.gov`، `*.noaa.gov`، `*.usgs.gov`، `*.usda.gov`، `medlineplus.gov`.
الروابط مقيّدة بقائمة `SCIENTIFIC_SOURCE_ALLOWLIST` في `config.py`.
قواعد يفرضها المحمِّل قبل الكتابة:
- لا تُصنَّف معلومة علمية «حقيقة مثبتة» إلا مع `url` واقتباس حرفي `quote` من الصفحة و`verified_at`؛
  وإلا تبقى «ادعاء غير موثق». معطيات NOAA في ملف النور 40 منقولة من الوثيقة ولم تُطابَق مع NOAA بعد.
- كل مقارنة «ارتباط محتمل» بحالة «مسودة» حتى يراجعها الباحث.
- معاني الألفاظ لا تُكتب في الملف؛ تؤخذ من كتب الغريب المستوعبة.

## النسخة التجريبية (صفحة واحدة بلا خادم)
تجمع الواجهة الحقيقية نفسها مع بياناتها في ملف HTML واحد: الطبقات كاملة للآيات النموذجية، والبحث في كل الآيات.
```bash
cd backend && python -m app.demo_export ../frontend/demo/data.json
cd ../frontend && node demo/build.mjs demo/afaq-demo.html
```
في وضع التجربة (`NEXT_PUBLIC_DEMO=1`) تُجاب طلبات الواجهة من البيانات المضمّنة، وروابط الآيات بصيغة `#v24-40`،
وصفحة المراجعة غير متاحة.

## مراجعة الباحث للمقارنات
الوثيقة تجعل المقارنات العلمية من عمل الباحث، فكل مقارنة «مسودة» حتى يعتمدها باحث من صفحة **`/review`**.
```bash
export AFAQ_REVIEWERS="د. أحمد:رمز-سري-طويل;د. سارة:رمز-آخر-طويل"   # رمز لكل باحث (16 حرفًا على الأقل)
python -m app.reviews --export   # كتابة القرارات في backend/curation/*.json لتُحفظ في git
```
- يدخل الباحث برمزه، ويرى لكل مقارنة: الآية، ومعنى اللفظ عند أهل الغريب، والمعلومة العلمية بمصدرها وحالة توثيقها،
  ونص المقارنة القابل للتعديل، وسجل المراجعات.
- القرارات: **اعتماد** (أو اعتماد بعد التعديل: يحل النص المعدّل محل الأصلي) — **طلب تعديل** (تبقى ظاهرة «قيد المراجعة»)
  — **رفض** (تختفي من الموقع). طلب التعديل والرفض يتطلبان ملاحظة.
- في الموقع تظهر المعتمدة «اعتمدها الباحث: الاسم — التاريخ»، والباقية «مسودة — بحاجة لمراجعة الباحث».
- القرار مرتبط بالنص الذي رُوجع: إن عُدّل نص المقارنة في ملفها بعد ذلك، عادت «مسودة» تلقائيًا لتُراجع من جديد.
- `--export` يكتب القرارات الفعلية فقط (الحالة، المراجع، التاريخ، والنص المعتمد) فتصبح جزءًا من الملفات في git.

## قراءات الإعجاز من quran-m.com (فهرسة بالروابط فقط)
```bash
python -m app.ingestion.ingest_quran_m   # 1093 مقالًا عبر واجهة WordPress العامة، طلب كل ثانية
```
- الموقع ينص على «جميع الحقوق محفوظة»، فلا يُنسخ نص المقالات: يُحفظ العنوان والرابط والتاريخ والتصنيف ومقتطف قصير
  (≤ 280 حرفًا)، ويقرأ المستخدم المقال في موقعه. `robots.txt` يسمح بكل شيء عدا صفحات البحث.
- ربط المقال بالآية: إحالة صريحة مثل «[النمل: 18]» أو «[الرحمن: 19-20]»، أو اقتباس بين ﴿ ﴾ من 3 كلمات فأكثر
  يطابق 3 آيات على الأكثر في البحث. النتيجة الحالية: 454 مقالًا مرتبطًا بـ 2073 آية.
- كل رابط «ارتباط محتمل»: قراءة من مصدر ثانوي، ليست تفسيرًا، ولم يتحقق آفاق من معلوماتها العلمية. ويُعرض تصنيف المقال
  (علمي، بياني، تشريعي، شبهات وردود) لأن مقالات الموقع ليست كلها علمية. تُقدَّم المقالات المركّزة على الآية أولًا.

## مقارنات الآيات ذات الموضوع المشترك
كل ملف في `backend/curation/` يعلن في `related_topics` الموضوعات القرآنية (من Quranpedia) التي تخصها مقارنته.
الآية التي لم تُعدّ لها مقارنة، وتشترك مع آية معدّة في أحد هذه الموضوعات، تعرض رابطًا إلى مقارنات تلك الآية.
الموضوعات العامة (مثل «الدِّين») لا تُعلن فلا تربط آيات غير ذات صلة.

**التغطية الحالية:** 20 آية بمقارنة موثقة المصادر، و107 آيات تصل إلى مقارنة عبر موضوع مشترك، و2073 آية لها مقالات
إعجاز مفهرسة؛ المجموع 2101 من 6236 آية. الآيات الباقية (الأحكام، القصص، العقيدة...) تعرض صراحة أنه لا توجد مقارنة علمية.

## البحث في نص الآيات
يكتب المستخدم جزءًا من الآية فتظهر كل الآيات التي تحتويه (اسم السورة، رقم الآية، النص)، ثم يختار الآية لعرض تفسيرها.
- `GET /search?q=<نص>&limit=50&offset=0` — يُرجع `total` (العدد الكلي) و`results` بترتيب المصحف؛ زر «عرض المزيد»
  في الواجهة يطلب الصفحة التالية بـ `offset` = عدد النتائج المعروضة.
- التطابق يتجاهل التشكيل وعلامات الضبط والوقف، ويوحّد (أ إ آ ٱ ← ا، ى ← ي، ة ← ه، ؤ ← و، ئ ← ي)،
  ويُقارَن بالنص الإملائي وبالنص العثماني معًا: «الصلاة» و«الصلوة» و«ٱلصَّلَوٰةَ» كلها تجد الآيات نفسها.
- التوحيد للمطابقة فقط؛ النص المعروض هو النص المخزَّن حرفيًا. الحد الأدنى حرفان عربيان.

## التفسير: ملفات Quranpedia الرسمية (dumps)
سياسة Quranpedia تمنع الزحف الجماعي على الـ API (الحد 10,000 طلب/يوم) وتوجّه إلى
`https://api.quranpedia.net/dumps`: ملف لكل كتاب تفسير (`tafsir-book-{id}.json.gz`) يضم نصه لكل الآيات.
- `ingest_tafsir_dump` ينزّل كل كتاب مرة واحدة (تخزين مؤقت في `backend/data/quranpedia/`، خارج git)،
  ويحفظ النص حرفيًا مع رقم الصفحة، ويسجّل تاريخ نسخة الملف في `sources.version`.
- افتراضيًا: الكتب التي يصنّفها Quranpedia «أساسية» (السعدي، الطبري، ابن كثير، الجزائري، المختصر،
  الميسر، أضواء البيان، الرفاعي، الصحيح المسبور) — نحو 43,600 مدخل تغطي الآيات الـ 6236، في أقل من دقيقة.
- ابن كثير بنسخة واحدة: 136 (دار طيبة، تحقيق سامي سلامة). النسخة 331 مستبعدة افتراضيًا (`EXCLUDED_DEFAULT_TAFSIR_BOOKS`
  في `config.py`) لأن مقاطعها تتداخل مع الآيات المجاورة؛ لحذفها من قاعدة قائمة: `--remove 331`.
- الرخصة (`dumps/LICENSE.md`): الاستعمال داخل التطبيقات مجاني؛ إعادة نشر البيانات كقاعدة بيانات قابلة للتنزيل
  تستلزم ذكر Quranpedia.net ورقم النسخة. المحتوى يُصحَّح باستمرار؛ التحديث عبر `/v1/changes?since=<version>`.
- `ingest_tafsir --surah N` (عبر الـ API) باقٍ لجلب سورة واحدة؛ المساران يشتركان في نفس سجل المصدر لكل كتاب
  فلا يتكرر التفسير.

## الأحاديث: الموسوعة الحديثية من الدرر السنية (Dorar.net)
واجهة `https://dorar.net/dorar_api.json?skey=<كلمات>` تبحث في **الأحاديث** بالكلمات، وليست مصدر تفسير.
```bash
python -m app.ingestion.ingest_hadith --surah 2 --ayah 43 --query "الصلاة"
```
- تُخزَّن كل نتيجة في `hadith_entries` بحقولها (النص، الراوي، المحدث، المصدر، الصفحة أو الرقم، حكم المحدث)
  مع كتلة HTML الأصلية للتدقيق.
- الربط بالآية مجرد تطابق نصي، فكل صف `POSSIBLE_CONNECTION` ويُعرض في قسم مستقل عن التفسير مع حكم المحدث دائمًا
  (النتائج تشمل أحاديث ضعيفة وموضوعة).
- كلمات البحث يحددها المستخدم صراحة (`--query`)؛ لا تُستنتج آليًا من الآية.
- **حماية Cloudflare في dorar.net تحظر خوادم السحابة**، فشغّل هذا الأمر من جهازك. الاختبارات تعمل بلا شبكة
  على استجابة حقيقية محفوظة (`backend/tests/fixtures/dorar_api_salah.json`).
- تفسير الدرر ("موسوعة التفسير المحرر") غير متاح عبر هذه الواجهة؛ يحتاج إذنًا أو ملف تصدير من الدرر.
- أُضيف جدول جديد `hadith_entries` (يُنشئه `init_db()` تلقائيًا).

## الذكاء الاصطناعي في الإعجاز العلمي (`/ai-ijaz`)

باحث آلي محايد يدرس العلاقة بين الآية والمعرفة العلمية، ولا يبدأ من فرضية الإعجاز: «لا يوجد إعجاز علمي مثبت»
نتيجة مقبولة مثل غيرها. تقريره **ادعاء غير موثق** حتى يراجعه باحث.

**الملفات** (`backend/app/ai_research/`):
| الملف | دوره |
|---|---|
| `prompt.py` | تعليمات الباحث (`RESEARCH_PROMPT`، النسخة `2026-10-05`)، ورسالة الآية مع حزمة مصادرها |
| `context.py` | حزمة المصادر القرآنية للآية من قاعدة آفاق: التفاسير (الميسر أولًا) ومعاني الغريب والإعراب والموضوعات، بمعرّفات Q1… ومقتطعة بطول محدود |
| `schema.py` | مخطط JSON الذي يملؤه النموذج (Structured Outputs، strict) |
| `providers.py` | المزودون: `mock` (الاختبار)، `openai` (Responses API)، `http` (أي منصة chat-completions بلا أدوات) |
| `report.py` | فحص التقرير قبل عرضه، ثم كتابته بالعربية |
| `api.py` | الواجهات، والبحث كمهمة في الخلفية تُتابَع مراحلها |

**المنهج** (في التعليمات): فهم الآية من حزمة المصادر ← تحديد الادعاء العلمي المحتمل (أو «لا يوجد») ← بحث علمي
مستقل عن الظاهرة نفسها لا عن «الإعجاز» ← تاريخ المعرفة ← المقارنة ← مقاومة الانحياز التأكيدي ← النقد ← التقييم
على ثلاث خطوات: الادعاء العلمي، ثم التطابق مع النص، ثم التقييم النهائي بأحد المستويات: Very Strong، Strong، Possible،
Weak، Unsupported، Contradicted، أو «لا يوجد ادعاء علمي قابل للدراسة».

**ما تتحقق منه آفاق آليًا** (`report.py`)، لأن التعليمات وحدها لا تمنع الاختلاق:
- المصادر القرآنية: تُقبل معرّفات الحزمة المرسلة (وملفات File Search) فقط، وأسماؤها من سجلات آفاق لا من النموذج.
- المصادر العلمية: يُعرض الرابط فقط إن كان بين الصفحات التي أعادها بحث الويب فعلًا في هذا التقرير
  (`include: ["web_search_call.action.sources"]`)؛ وإلا يُحذف الرابط، حتى من داخل نص النموذج، ويُعلَّم المصدر «غير متحقق منه».
- تقييم Very Strong أو Strong بلا أي مصدر علمي متحقق منه يُخفَّض إلى Possible، ويُذكر ذلك في التقرير.
- فشل البحث على الإنترنت أو غيابه يُذكر في «حدود هذا البحث»، ولا يُعوَّض من ذاكرة النموذج.

**الواجهات:**
- `GET /ai-research/status` — المزود والنموذج والأدوات والتعليمات.
- `GET /ai-research/report?surah_number=&ayah_number=` — تقرير الآية المحفوظ (لا يُنشئ تقريرًا مدفوعًا).
- `POST /ai-research` — في وضع الاختبار أو لتقرير محفوظ: 200 بالتقرير. مع منصة متصلة: 202 بمعرّف مهمة
  (البحث الكامل يستغرق دقائق)، و`GET /ai-research/jobs/{id}` يعطي مراحلها ثم التقرير. لا يُبدأ البحث نفسه مرتين.
- كل تقرير يُحفظ في `ai_reports` (الآية، نسخة التعليمات، النموذج) مع JSON المفحوص، فيُدفع ثمنه مرة واحدة.

**التشغيل مع OpenAI:** في `.env` ضع `AFAQ_AI_PROVIDER=openai` و`OPENAI_API_KEY` (في الخادم فقط، لا يصل إلى المتصفح
ولا يُكتب في السجلات أو رسائل الخطأ). الإعدادات الاختيارية في `.env.example`:
- `OPENAI_MODEL`: الافتراضي `gpt-6.1-sol`، وقد تحققت من وجوده في توثيق OpenAI في 2026-10-05.
- `OPENAI_REASONING_EFFORT`: الافتراضي `high`.
- `OPENAI_VECTOR_STORE_IDS`: لتفعيل File Search على كتب مرجعية إضافية.
- `OPENAI_WEB_SEARCH`.
- `AFAQ_AI_TIMEOUT`.

**الحد من التكلفة:** عدد محدود من التقارير لكل عنوان في الساعة (`AFAQ_AI_HOURLY_LIMIT`، الافتراضي 10، و0 بلا حد).
والتعليمات الثابتة تُرسل أولًا، فتستفيد من التخزين المؤقت لدى OpenAI. وضع الاختبار مجاني وبلا حد.

**النشر على Render:** ملف `render.yaml` جاهز، والخطوات في [`DEPLOY_RENDER.md`](DEPLOY_RENDER.md). **عند النشر على نطاق:** ضع عنوان الواجهة في `AFAQ_CORS_ORIGINS` (مثل `https://afaq.example.com`)، وتُبنى الواجهة
مع `NEXT_PUBLIC_API_BASE` = عنوان الخادم. المهام في ذاكرة العملية، فيُشغَّل الخادم بعامل (worker) واحد، أو تُنقل المهام إلى طابور مشترك.

و`GET /surah/{n}` (آيات السورة بنصها الحرفي مع `curated` و`ijaz_articles`)، و`GET /page/{n}` (آيات صفحة المصحف وجزؤها،
والبسملة: نص الفاتحة 1 المخزّن دون علامة نهاية الآية، تُعرض رأسًا لكل سورة تبدأ في الصفحة عدا التوبة). النسخة التجريبية الثابتة تعرض الأقسام نفسها بمسارات `#home` و`#search` و`#history`
و`#quran?p=355` و`#ai-v24-40` (انظر `frontend/app/components/links.ts`).

## البحث بالموضوع (`GET /search/topics?q=`)

يكتب المستخدم موضوعًا مثل «مدة الرضاعة الطبيعية» بدل كلمات الآية، فتظهر الآيات التي تربطها مصادر آفاق به،
الأقوى صلة أولًا، ومع كل آية سبب ظهورها. لا يخمّن نموذجٌ الصلة؛ مصادرها (بوزن كلٍّ منها):
المقارنات العلمية المعدّة (5)، وفهرس موضوعات Quranpedia وموضوعه الأب (3)، وعناوين مقالات الإعجاز (2)،
ونص التفسير الميسر إذا ذكر كلمات البحث (1). التفاصيل في `backend/app/topic_search.py`:
- المطابقة بالكلمات بعد جذع خفيف (أداة التعريف، الضمائر المتصلة، اللواحق الشائعة)، فـ«الرضاعة» تطابق «الإرضاع»
  و«مدتها» تطابق «مدة»، ولا تطابق «رضا» كلمة «مرضاة».
- كل كلمة بوزن ندرتها في المصادر، فـ«الرضاعة» أثقل من «مدة»؛ والمطابقة الجزئية تُرتَّب بعد الكاملة.
- تُقبل المصدر إذا حملت كلماته المطابقة نصف وزن البحث على الأقل. والكلمات المعطوفة بالواو («البرق والرعد») يكفي فيها
  مطابقة نصفها. أما الإضافة («ذكاء الإنسان») فلا يكفي فيها المضاف إليه وحده، وإلا ظهرت كل آيات «الإنسان».
- إذا قلّت النتائج عن 10 تُضاف الآيات المطابقة لموضوع العبارة وحده، وهو أندر كلماتها في المصادر: «الرضاعة» في
  «مدة الرضاعة الطبيعية»، و«ذكاء» في «ذكاء الإنسان».
- **جموع التكسير وصيغ الكلمة:** يعطي Quranic Arabic Corpus لكل كلمة قرآنية لمّتها (lemma)، فتُطابَق «البحار» بـ«البحر»
  و«الجبال» بـ«جبل» و«الرياح» بـ«ريح». وحين تُعرف لمّتا الكلمتين تحكم اللمّة لا الجذع، فلا تُطابَق «لبنيه» (لِ + بنيه، لمّتها «ابن») بـ«لبن».
  اللمّة لا الجذر: الجذر أوسع من اللازم (ريح وروح من جذر واحد).
- **المترادفات:** قائمة معدّة قابلة للمراجعة في `backend/app/synonyms.json` (مثل المطر والغيث، الجبال والرواسي، الفطام والفصال،
  اللبن والحليب). المطابقة بمرادف تُحسب بـ0.8 من المطابقة بالكلمة نفسها، ولا تُستعمل مع نص التفسير، وتذكر النتيجة المرادف
  الذي جاءت به («موضوع: الجبال — بمرادف «جبل»»). القاعدة: اللغة لا التأويل؛ لا تُضاف كلمة لأن مقالًا يربطها بالآية.

صفحة البحث تُرسل كل استعلام إلى البحثين معًا، وتعرض تبويبين: «حسب الموضوع» و«نص الآية»، وتختار الأنسب تلقائيًا.
النسخة التجريبية تنفّذ البحث نفسه في المتصفح (`frontend/demo/topicSearch.ts`)، و`node demo/check-topic-search.mjs`
يتحقق من تطابق نتائجها مع الخادم.

يبني الخادم فهرس البحث بالموضوع وفهرس نص الآيات عند تشغيله، في الخلفية، فلا ينتظر أول باحث بناءهما (نحو 5 ثوانٍ
على البيانات الكاملة). `AFAQ_WARM_INDEX=0` يعطّل ذلك فيُبنى الفهرس عند أول بحث.

## الواجهة: قرارات الاستعمال

- **الجوال:** الأقسام شريط تبويب أسفل الشاشة. عند اختيار آية من النتائج تظهر الآية أولًا وتُطوى النتائج خلف زر
  «العودة إلى النتائج (العدد)»، الذي يعيد القائمة عند الآية المختارة (والزر نفسه على الحاسوب يمرّر إليها).
- **صفحة الآية أقصر:** الطبقات قابلة للطي (اللغوية والمفاهيم والأحاديث مطوية ابتداءً، ويفتحها شريط الطبقات أو زر
  «عرض»)؛ وفي التفسير يأتي «المعنى الإجمالي» من التفسير الميسر أولًا ثم التفاسير المفصّلة، وكلٌّ منها أربعة أسطر
  مع «اقرأ المزيد». شارات فئات الثقة الخمس صارت «ما معنى الألوان؟» تحت الآية. ونسخ نص الآية ومشاركة رابطها
  تحت الآية وفي لوحة الآية في المصحف.
- **النتائج:** سطران من كل آية، وتأخذ عرض الصفحة كاملًا ما لم تُختر آية.
- **المصحف:** علامات الإعجاز تحت الآيات مخفية ابتداءً ليُقرأ كالمصحف، ويُظهرها «إظهار علامات الإعجاز» (يُحفظ الاختيار
  في المتصفح)؛ ومفتاح الألوان فوق الفهرس والصفحة، ولكل علامة تلميح.
- **الأرقام** بالأرقام العربية المشرقية (٢٤) في الواجهة كلها، وفلتر السور يقبل الرقمين. أصغر نص 12px، وأزرار الجوال 40px على الأقل.
- التذييل نفسه في كل الصفحات.

## الهوية البصرية «المِداد»

- **الألوان** (`frontend/app/globals.css`): ورق دافئ `#F6F2E9`، وحبر أخضر داكن `#12302F` للنص، وأخضر واحد للأزرار `#1F5C57`،
  وذهبي `#A8823A` للزخرفة فقط (الشعار، إطار صفحة المصحف، عنوان السورة). ألوان فئات الثقة الخمس ثابتة المعنى، وهي الألوان الوحيدة الأخرى.
  الوضع الداكن: الحبر نفسه أرضيةً والورق نصًّا.
- **الشعار** (`components/Logo.tsx`، و`app/icon.svg`): قوس شمس ذهبي فوق خط الأفق، مع «آفاق» بخط Reem Kufi.
- **الخطوط** تُخدَم من المنصة نفسها (`public/fonts`، `app/fonts.css`) لا من Google Fonts: القرآن بخط مجمع الملك فهد،
  والنصوص العلمية (التفسير والإعراب) بـNoto Naskh Arabic، والواجهة بـIBM Plex Sans Arabic، والعناوين بـReem Kufi.
  الثلاثة الأخيرة برخصة SIL OFL (`public/fonts/OFL-*.txt`)، من Fontsource بمجموعتي الحروف العربية واللاتينية.
  النسخة التجريبية تضمّنها في الصفحة، فتعمل دون اتصال.

## البحث بالموضوع بالذكاء الاصطناعي (`GET /search/ai?q=`)

تبويب «✦ بالذكاء الاصطناعي» في صفحة البحث يرسل الموضوع («ذكاء الإنسان») إلى منصة الذكاء الاصطناعي، فتقترح الآيات
المتصلة به مع سبب كل واحدة (`backend/app/ai_research/topic.py`). وبما أن النموذج قد يذكر آية غير موجودة أو رقمًا خاطئًا،
يُطلب منه اقتباس كلمات من كل آية، ولا يُعرض شيء دون تحقق:
- يجب أن توجد الآية وأن يوجد الاقتباس فيها (بتجاهل التشكيل واختلاف الرسم والألف: «السماوات» = «السموات» في المصحف).
- إن لم يوجد في الآية المذكورة ووُجد في آية واحدة أخرى (أو في آية واحدة من السورة المذكورة) صُحّح الرقم وذُكر ذلك.
- غير ذلك تُحذف الآية، وتذكر الصفحة عدد المحذوف.
- النص المعروض هو نص المجمع المخزّن دائمًا، والسبب كلام النموذج موسوم «ادعاء غير موثق».
- يُحفظ جواب كل موضوع (200 موضوع في الذاكرة) فلا يُدفع ثمنه مرتين، ويخضع لحد `AFAQ_AI_HOURLY_LIMIT`.

في وضع الاختبار (قبل ربط المنصة) يجيب البحث بالمصادر الموصوف أعلاه (`/search/topics`)، وتقول الصفحة ذلك صراحة.

## الذكاء الاصطناعي في رحلة الآية

صفحة الآية (`/search?v=24:40`) فيها طبقة خامسة «الذكاء الاصطناعي في الإعجاز العلمي» بعد «المعرفة العلمية»:
- في وضع الاختبار يظهر التقرير التجريبي مع النتائج مباشرة.
- مع منصة متصلة يظهر تقرير الآية المحفوظ إن وُجد، وإلا زر «أنشئ تقرير الذكاء الاصطناعي»: لا يُنشأ تقرير مدفوع لمجرد فتح آية.
- كل تقرير من منصة متصلة يُحفظ في جدول `ai_reports` (الآية، نسخة التعليمات، النموذج)، فيُدفع ثمنه مرة واحدة:
  `GET /ai-research/report` يعيده دون إنشاء، و`POST /ai-research` يعيده إن وُجد ولا يُحتسب من حد الساعة.
